# 06. 링크 계층: 바로 옆 칸까지는 MAC 주소로 간다

IP 주소는 "최종 목적지"입니다. 하지만 전파나 케이블로 실제 신호를 보낼 때는 **같은 네트워크 안의 바로 다음 기기**에게만 보낼 수 있습니다. 그 기기를 가리키는 주소가 **MAC 주소**(네트워크 카드마다 붙은 6바이트 고유 번호)입니다.

- **IP 헤더**: 출발 192.168.30.149 → 도착 104.20.23.154(example.com). 끝까지 바뀌지 않습니다.
- **Ethernet 헤더**: 출발 내 MAC → 도착 **공유기(게이트웨이) MAC**. 라우터를 하나 지날 때마다 새로 붙습니다.

내 PC는 IP 주소만 알고 있는데 공유기의 MAC은 어떻게 알까요? 그 일을 하는 것이 **ARP**(같은 네트워크 전체에 "이 IP 가진 기기 누구야?"라고 방송해서 MAC을 알아내는 규약)입니다.

이 실습에는 코드가 없습니다. 모두 **Wi-Fi(또는 이더넷) 어댑터**에서 캡처합니다.

## 1) 내 네트워크 정보 확인

```powershell
ipconfig
```

```powershell
arp -a
```

- `ipconfig`에서 내 IPv4 주소, 서브넷 마스크, **기본 게이트웨이**를 적어 둡니다. 이 문서를 쓸 때는 각각 192.168.30.149, 255.255.255.0, 192.168.30.1이었습니다.
- `arp -a`는 Windows가 기억하는 "IP → MAC" 표(ARP 캐시)입니다. 게이트웨이 IP 옆의 **물리적 주소**를 적어 둡니다. 이 문서를 쓸 때는 `00-00-5e-00-01-1e`였습니다.

## 2) 인터넷으로 가는 패킷의 도착 MAC은 누구인가

필터: `ip.addr == 104.20.23.154`

```powershell
curl.exe -s -o NUL http://example.com/
```

패킷 하나를 골라 맨 위의 **Ethernet II**를 펼칩니다.
- **Destination**: example.com의 MAC이 아니라 1)에서 적은 **게이트웨이 MAC**입니다.
- **Source**: 내 Wi-Fi 카드의 MAC입니다. `ipconfig /all`의 "물리적 주소"와 같습니다.
- **Type**: `IPv4 (0x0800)`. Ethernet 헤더 다음에 IP가 온다는 뜻입니다.
- 그 아래 IP 층을 펼치면 도착 IP는 104.20.23.154입니다. **IP는 최종 목적지, MAC은 바로 다음 칸**이라는 것을 한 패킷 안에서 동시에 볼 수 있습니다.

## 3) ARP 직접 일으키기

같은 네트워크(192.168.30.x) 안에서 **아무도 쓰지 않는 주소**로 ping을 보냅니다. 그러면 Windows는 그 주소의 MAC을 모르므로 먼저 ARP로 묻습니다.

필터: `arp`

```powershell
ping -n 1 192.168.30.250
```

주소는 1)에서 본 내 네트워크 범위 안에서, `arp -a`에 없는 번호를 고릅니다.

- `Who has 192.168.30.250? Tell 192.168.30.149`가 찍힙니다.
- 이 패킷의 Ethernet 도착 MAC은 `ff:ff:ff:ff:ff:ff`입니다. **브로드캐스트**(같은 네트워크의 모든 기기에게 보냄)입니다. 누구의 MAC인지 모르니 모두에게 묻는 것입니다.
- ARP 본문의 Target MAC은 `00:00:00:00:00:00`입니다. 아직 모르는 값이라 0으로 채웁니다.
- 이 PC에서는 대답이 없어서 약 0.6초 간격으로 3번 물은 뒤 포기했습니다. ping은 "대상 호스트에 연결할 수 없습니다"로 끝납니다.
- 캡처를 켜 두면 **다른 기기들의 ARP 방송**도 계속 보입니다. 브로드캐스트라서 내 PC에도 도착하기 때문입니다.

`arp -d`로 캐시를 지우고 게이트웨이에 다시 묻게 할 수도 있습니다. 하지만 이 명령은 관리자 권한이 필요합니다. 캐시는 몇십 초 정도 쓰이지 않으면 저절로 사라지므로, 잠시 뒤 다시 캡처하면 게이트웨이 ARP 요청과 응답(`192.168.30.1 is at ...`)을 볼 수도 있습니다.

## 4) loopback에는 링크 계층이 없다

01~02의 loopback 캡처를 다시 열고 패킷 하나를 펼쳐 보세요. 맨 위가 Ethernet II가 아니라 **Null/Loopback** 4바이트입니다. 127.0.0.1 통신은 네트워크 카드를 거치지 않으므로 MAC 주소가 필요 없습니다. "IPv4가 온다"는 표시만 남아 있습니다.
