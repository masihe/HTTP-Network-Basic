# 01. TCP 연결: 데이터가 오가기 전과 후

HTTP를 보기 전에, HTTP가 올라타는 **TCP**(두 프로그램 사이에 순서와 도착을 보장하는 연결을 만들어 주는 규약)를 먼저 봅니다.
여기서는 HTTP가 전혀 없습니다. `server.py`는 받은 바이트를 그대로 돌려주고, `client.py`는 `hello tcp` 한 줄을 보낸 뒤 연결을 닫습니다.

## 실행

터미널 두 개를 엽니다.

```powershell
python server.py
```

```powershell
python client.py --message "hello tcp"
```

포트를 바꾸려면 두 쪽에 모두 `--port 9001`처럼 넘깁니다.

## Wireshark로 보기

1. Wireshark에서 **Adapter for loopback traffic capture**를 더블클릭해서 캡처를 시작합니다. 127.0.0.1끼리의 통신은 실제 네트워크 카드를 지나지 않아서 이 어댑터에서만 보입니다.
2. 위쪽 필터 칸에 `tcp.port == 9000`을 입력합니다.
3. `client.py`를 실행합니다. 패킷이 열 개 안팎으로 찍힙니다.

### 관찰 포인트

| 순서 | Info 열에 보이는 것 | 뜻 |
|---|---|---|
| 1 | `[SYN]` | 클라이언트: "연결하고 싶다. 내 시작 번호는 이것이다" |
| 2 | `[SYN, ACK]` | 서버: "좋다. 네 번호를 받았고, 내 시작 번호는 이것이다" |
| 3 | `[ACK]` | 클라이언트: "네 번호를 받았다." 여기까지가 **3-way handshake**다 |
| 4 | `[PSH, ACK] Len=9` | 클라이언트가 `hello tcp` 9바이트를 보냄 |
| 5 | `[ACK]` / `[PSH, ACK] Len=9` | 서버가 받았다고 알리고, 같은 9바이트를 돌려줌 |
| 6 | `[FIN, ACK]` … `[ACK]` | 각자 "더 보낼 게 없다"고 알리고 연결을 닫음 |

- 4번 패킷을 클릭하고 아래쪽 바이트 창을 보면 `68 65 6c 6c 6f 20 74 63 70`(= `hello tcp`)이 그대로 보입니다. 암호화가 없으면 내용이 그대로 흘러간다는 뜻입니다.
- **Seq**(내가 보내는 바이트의 위치)와 **Ack**(다음에 받을 것으로 기대하는 위치)를 따라가 보세요. 9바이트를 보낸 뒤 상대의 Ack가 정확히 9만큼 늘어납니다. Wireshark는 기본으로 0부터 시작하는 상대 번호를 보여줍니다.
- 패킷 하나를 우클릭하고 **Follow → TCP Stream**을 누르면, 이 연결에서 오간 내용만 대화처럼 모아서 보여줍니다.
- 코드와 연결해서 보세요.
  - `socket.create_connection()` 한 줄 안에서 1~3번 패킷이 오갑니다.
  - 서버의 `accept()`는 handshake가 끝난 뒤에 돌아옵니다.
  - `recv()`가 빈 바이트(`b''`)를 돌려주는 순간이 상대가 FIN을 보낸 순간입니다.
