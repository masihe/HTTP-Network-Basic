# 07. 네트워크 계층: IP는 라우터를 건너뛰며 목적지를 찾아간다

06에서 패킷은 바로 옆 공유기까지만 MAC으로 갔습니다. 거기서부터 example.com까지는 **라우터**(IP 주소를 보고 다음에 보낼 곳을 정하는 장비)들이 차례로 넘겨 줍니다. 이 일이 IP 층의 몫입니다.

이 실습에서는 IP 헤더의 세 가지 칸을 봅니다.

| IP 헤더 칸 | 하는 일 | 보는 방법 |
|---|---|---|
| **TTL** | 라우터를 지날 때마다 1씩 줄고, 0이 되면 그 라우터가 패킷을 버리고 알려 줌 | `ping`, `tracert` |
| **프로토콜** | IP 다음에 오는 것이 TCP(6)인지 UDP(17)인지 ICMP(1)인지 표시 | 모든 패킷 |
| **식별자 / 플래그 / 조각 위치** | 큰 패킷을 쪼갰을 때 다시 맞추기 위한 정보 | `ping -l 3000` |

**ICMP**는 IP가 오류나 상태를 알릴 때 쓰는 보조 규약입니다. "TTL이 다 됐다", "그 포트는 아무도 안 받는다" 같은 소식을 전합니다. ping도 ICMP입니다.

모두 **Wi-Fi(또는 이더넷) 어댑터**에서 캡처하고, 필터는 `icmp || ip.flags.mf == 1 || ip.frag_offset > 0`을 씁니다.

## 1) ping: TTL로 거리 짐작하기

```powershell
ping -n 2 example.com
```

- `Echo (ping) request`(ICMP 타입 8)와 `Echo (ping) reply`(타입 0)가 짝으로 찍힙니다.
- 내 요청의 TTL은 **128**입니다. Windows의 시작값입니다.
- 이 PC에서 돌아온 응답의 TTL은 **55**였습니다. 리눅스 서버는 보통 64에서 시작합니다. 그래서 64 - 55 = 약 9개의 라우터를 지나 왔다고 짐작할 수 있습니다.

## 2) TTL을 일부러 작게: 라우터가 대답하게 만들기

```powershell
ping -n 1 -i 1 example.com
```

```powershell
ping -n 1 -i 2 example.com
```

`-i`는 TTL 시작값입니다. TTL이 0이 된 라우터는 패킷을 버리고 **`Time-to-live exceeded`(ICMP 타입 11)**를 내 PC로 보냅니다. 응답의 출발 IP가 그 라우터의 주소입니다.

이 원리를 자동으로 반복하는 명령이 `tracert`입니다.

```powershell
tracert -d -h 10 example.com
```

TTL 1, 2, 3…으로 3번씩 보내면서, 각 단계에서 대답한 라우터를 줄마다 보여 줍니다.

**이 네트워크에서 확인한 것**:
- 2번째 라우터(192.168.1.20)만 대답했고, 나머지 단계는 `*`(시간 초과)였습니다.
- 1번째 단계도 `*`입니다. 교육용이나 회사 네트워크는 보안 때문에 라우터가 TTL 초과 알림을 보내지 않게 막는 경우가 많습니다.
- 그래도 ping 자체는 목적지까지 갑니다. TTL이 충분하면 막힌 라우터도 그냥 넘겨 주기 때문입니다.

Wireshark에서 tracert의 요청 패킷들을 보면 IP 헤더의 TTL이 1, 1, 1, 2, 2, 2, 3…으로 늘어납니다. TTL 초과 응답을 펼쳐 보면, ICMP 안에 **내가 보냈던 원래 IP 헤더**(TTL=1)가 통째로 들어 있습니다. 라우터가 "네가 보낸 이 패킷이 죽었다"고 증거를 붙여 돌려주는 것입니다.

## 3) IP 분할: 너무 큰 패킷을 쪼개기

한 번에 보낼 수 있는 최대 크기를 **MTU**라고 합니다. Wi-Fi와 이더넷은 보통 1500바이트입니다. 그보다 큰 IP 패킷은 쪼개서 보냅니다.

```powershell
ping -n 1 -l 3000 example.com
```

`-l 3000`은 ping 데이터를 3000바이트로 만듭니다. ICMP 헤더 8바이트를 더하면 3008바이트라 1500에 들어가지 않습니다.

이 PC에서 본 조각은 다음과 같습니다.

| 조각 | IP ID | MF(뒤에 더 있음) | 조각 위치 | IP 전체 길이 |
|---|---|---|---|---|
| 1 | 0x3a88 | 1 | 0 | 1500 |
| 2 | 0x3a88 | 1 | 1480 | 1500 |
| 3 | 0x3a88 | 0 | 2960 | 68 |

- 세 조각의 **ID가 같습니다**. 받는 쪽은 이 번호로 같은 패킷의 조각을 모읍니다.
- 조각 위치가 1480씩 늘어납니다. 1500에서 IP 헤더 20바이트를 뺀 값입니다.
- ICMP 헤더는 **첫 조각에만** 있습니다. Wireshark는 마지막 조각이 도착했을 때 다시 맞춘 결과를 `Echo (ping) request`로 보여 줍니다.
- 응답도 똑같이 3조각으로 돌아옵니다.
