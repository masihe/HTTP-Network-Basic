# 09. 캡슐화 해부: 패킷 하나를 바이트 단위로 직접 자르기

지금까지 Wireshark가 계층별로 예쁘게 펼쳐 준 것을 봤습니다. 이번에는 그 일을 직접 합니다.
`dissect.py`는 패킷 하나의 원본 바이트를 받아서, 정해진 자리에서 헤더를 잘라 해석합니다. "앞의 14바이트는 Ethernet, 다음 20바이트는 IP"처럼 자르는 방식입니다.

**캡슐화**는 위층의 데이터 앞에 아래층이 자기 헤더를 붙여 감싸는 것입니다. 받는 쪽은 바깥부터 한 겹씩 벗깁니다.

```
[Ethernet 14][IP 20][TCP 20][GET / HTTP/1.1 ...]
 ↑ 06        ↑ 07   ↑ 01·08  ↑ 02
 다음은 IP다   다음은 TCP다   다음은 80번 포트 프로그램에게
 (EtherType)  (프로토콜 번호)  (포트 번호)
```

각 헤더에는 "내 다음에 무엇이 오는지"를 알려 주는 칸이 있습니다. 그래서 바깥부터 차례로 읽을 수 있습니다.

## 실행

1. Wireshark에서 패킷 하나를 우클릭하고 **Copy → ...as a Hex Stream**을 고릅니다.
2. 붙여 넣어 실행합니다.

Wi-Fi나 이더넷에서 캡처한 패킷은 다음처럼 실행합니다.

```powershell
python dissect.py "00005e00011ed4f32d313008080045000073..."
```

loopback에서 캡처한 패킷은 링크 계층 모양이 달라서 `--link null`을 붙입니다.

```powershell
python dissect.py --link null "020000004500002511..."
```

출력의 `[  34..  35]`는 이 필드가 패킷의 34~35번째 바이트(0부터 셈)라는 뜻입니다. Wireshark 아래쪽 바이트 창에서 같은 자리를 클릭해 맞춰 보세요.

## 해부해 볼 패킷

| 순서 | 어디서 캡처 | 고를 패킷 | 볼 것 |
|---|---|---|---|
| 1 | 03 실습 (Wi-Fi) | `GET / HTTP/1.1` | 4계층이 모두 있는 전형적인 모양. 데이터 칸에 HTTP 텍스트가 그대로 있음 |
| 2 | 08의 UDP (loopback, `--link null`) | `hello udp` 요청 | 링크 헤더 4바이트, UDP 헤더 8바이트. TCP보다 훨씬 짧음 |
| 3 | 06의 ARP (Wi-Fi) | ARP 요청 | IP 층이 없음. EtherType `0x0806` 다음에 바로 ARP |
| 4 | 07의 `ping -l 3000` (Wi-Fi) | 두 번째 조각 | 전송 계층 헤더가 없음. 첫 조각에만 있음 |
| 5 | 07의 tracert (Wi-Fi) | `Time-to-live exceeded` | 라우터가 보낸 ICMP. 데이터 안에 내가 보낸 원래 IP 헤더가 들어 있음 |

## 이 PC에서 만난 것들

- **내가 보낸 패킷의 IP 체크섬이 `0x0000`**: Wi-Fi에서 캡처한 내 요청의 체크섬 칸이 비어 있었습니다. 체크섬은 네트워크 카드가 내보내기 직전에 채우는데(checksum offload), Npcap은 그보다 앞에서 패킷을 복사하기 때문입니다. 상대가 보낸 패킷이나 loopback 패킷은 직접 계산한 값과 **일치**합니다.
- **VLAN 태그 `0x8100`**: 라우터에서 들어온 일부 패킷에는 EtherType 자리에 `0x8100`이 있고, 그 뒤 4바이트를 지나서야 진짜 EtherType(`0x0800`)이 나옵니다. 그래서 IP가 14번째가 아니라 18번째 바이트에서 시작합니다. 이 경우 `dissect.py`가 VLAN ID를 따로 보여 줍니다.
- **Seq 값이 Wireshark와 다름**: `dissect.py`는 헤더에 실제로 적힌 큰 숫자(절대값)를 보여 줍니다. Wireshark는 보기 편하게 연결 시작을 0으로 바꾼 상대값을 보여 줍니다. Wireshark에서 TCP를 펼치면 `Sequence Number (raw)`가 절대값입니다.
